# T2b blind pairs: a second judge (Gemini, web chat)

The same five pairs as `../reading_sheet.md`, judged by an outside model with the same four criteria (useful, clear,
trustworthy, cites properly), scored 1–5 each, with a JSON reply. Neither writer is Gemini, so it judges neither its own
writing nor a relative's.

## Why each pair is sent twice

Model judges are known to favour the report shown first, and the longer one. One writer's reports here run 2–3 times
longer than the other's. So:

- each prompt tells the judge that length and order count for nothing;
- each pair is sent once as A then B (`order_AB`) and once as B then A (`order_BA`), each in a new chat;
- a pair counts as a win for one report only if it wins in both orders; otherwise it counts as "same".

## Steps (about 15 minutes)

1. **Do your own reading first** (`../reading_sheet.md`), so Gemini's verdicts don't steer yours.
2. For each of the 10 files `pair_N_order_XY.txt`: open a **new** Gemini chat, paste the file's whole text, send, then
   copy the JSON reply into the table below. Don't upload or paste `key_do_not_open_before_reading.json`.
3. Note which Gemini model the chat used (shown in the model picker).
4. Send me the filled table (or save this file). I'll map "report 1/2" back to A/B, apply the both-orders rule, and add
   the result to T2b's results beside your verdicts and the checker's counts.

Gemini can't see the facts the writers were given, so it judges usefulness, clarity, internal consistency and citations.
The automatic checker already compared every number with the facts: 3 wrong numbers left for one writer, 15 for the
other. In `order_AB` report 1 is A; in `order_BA` report 1 is B.
